# 小满聊天与任务界面

手机（`crates/xiaoman-gpui`）和桌面（`crates/xiaoman-ui`）共用同一条交互线：状态在标题旁、过程可折叠、
审批卡固定在输入区上方、结果单独成卡。

| 位置 | 交互 |
|---|---|
| 标题 | 名称旁显示简短状态：已就绪 / 处理中 / 等你确认 / 待设置 |
| 会话 | 留白、轻量气泡、清楚的主次；助手结果用独立卡片，支持基础粗体和列表 |
| 过程 | 连续进度记录收进「处理过程」，点开才展开；问题、错误和最终回答始终可见 |
| 底栏 | 审批卡或技能草稿卡出现时替代输入行，自动收起键盘 |

## 审批卡

- 只有 `Decision::Ask` 才弹卡：拒绝和直接放行的操作不打扰用户。
- 默认只显示「暂不允许」和「允许一次」，「本次任务的同类操作都允许」在更多选项里。
- 卡片带 approval id；过期的卡片或通知不能回答新审批。
- 批准后回到目标 App 重新核对页面，不取消任何原有确认规则。

## 技能草稿卡

- 模型调用 `skill_edit` 后，卡片显示动作（新建 / 修改 / 删除）、技能名和完整 `SKILL.md`；
  修改时提示是否覆盖同名内置技能。
- 只有「保存」写盘；「取消」、退出或进程结束都不留文件。没有文字「确认」这条路径。
- 删除内置技能在校验阶段就被拒绝，卡片不会出现。
- 保存后切到「技能」页会重新加载，能看到新技能。

## 悬浮任务条

只在 Android、且小满页面不在前台时显示：显示当前状态与停止按钮，点击文字回到小满；执行手势和
截图时临时隐藏，避免挡住要操作的内容。

## 首页示例

示例提示词只填写一句可编辑的中文，需要用户点击发送才执行。购物类默认规则（普通规格、数量 1、
含运费预算、核对结算后停止）是模型指引；支付前仍依赖 Sentinel 的独立确认，不能把提示词当成权限控制。

真机验收应覆盖：大字体布局、中文发送、过程展开、审批卡、技能草稿卡、返回目标 App、停止、真实结果。
